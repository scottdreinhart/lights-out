# Package.json Line-by-Line Documentation

This document provides a comprehensive, line-by-line explanation of the root `package.json` file for the Game Platform monorepo. It serves as the authoritative reference for script usage, quality gates, and governance enforcement.

## Purpose & Audience

- **For Agents & Copilot**: Learn existing scripts to avoid token waste from inventing duplicates
- **For Developers**: Understand script segmentation and quality gate escalation
- **For Governance**: See how scripts enforce AGENTS.md rules and CLEAN architecture

## Key Principles

1. **Script Segmentation**: Scripts are organized by scope (app/domain/ui), type (a11y/security), and intensity (quick/standard/full/strict)
2. **Quality Gate Escalation**: Start with quick checks, escalate to full validation as needed
3. **Governance Integration**: Scripts enforce AGENTS.md § 0 (non-negotiable rules) and § 3-4 (architecture)
4. **Token Efficiency**: Always prefer existing scripts over creating new ones

## Token Efficiency Guidelines for Agents

### NEVER Create New Scripts

- **If you need linting**: Use existing `lint:scope:*` or `lint:type:*` scripts
- **If you need testing**: Use `test:*` variants, not custom grep patterns
- **If you need building**: Use `pnpm -C apps/{app} build`, not raw commands

### ALWAYS Prefer Existing Scripts

- **For quick checks**: `pnpm check` (lint + format + types)
- **For full validation**: `pnpm validate` (includes build + tests)
- **For app-specific work**: Use `pnpm -C apps/{app} {command}` pattern
- **For quality gates**: Start with `lint:gate:quick`, escalate as needed

### Script Discovery Strategy

1. **Check scope first**: `lint:scope:app` for app work
2. **Check type second**: `lint:type:a11y` for accessibility
3. **Check intensity third**: `lint:gate:quick` for fast feedback
4. **Combine as needed**: `lint:scope:app && lint:type:react`

This segmentation prevents token waste from running unnecessary full lints when scope-specific checks suffice.
